# 살아있는 지구 — 설계 노트

구현 전에 정리한 설계 문서. 아키텍처와 각 결정의 근거를 남겨둔다.

## 1. 개요

커스텀 Three.js 지구본 위에 실시간 데이터 레이어(지진, ISS, 위성)를 토글로 얹는 정적 웹사이트.
서버 없이 브라우저에서 무료 공개 API를 직접 호출한다.
핵심 서사: 낮/밤 경계·지진·ISS가 전부 **지금 이 순간**의 실제 상태다.

## 2. 아키텍처 & 기술 스택

### 스택

- Vite + TypeScript + Three.js (바닐라, React 없음)
- 근거: 본질이 3D 씬 하나 + 얇은 UI. React/r3f는 통합 비용만 추가.
  바닐라가 셰이더를 직접 다루기에 더 단순하다.
- 테스트: Vitest (유닛), Playwright (스모크)
- 배포: Vercel (정적 사이트). GitHub Pages도 가능.

### 디렉터리 구조

```
src/
  core/        # 씬, 카메라, 렌더 루프, 리사이즈
  globe/       # 지구 메시 + 셰이더 (낮/밤, 대기, 야경)
  layers/      # 데이터 레이어 (각각 독립 모듈, 공통 인터페이스)
    earthquakes.ts   # USGS API
    iss.ts           # ISS 실시간 위치
    satellites.ts    # 주요 위성 궤도 (TLE + satellite.js)
  data/        # API 클라이언트, 캐싱, 폴링, 백오프
  ui/          # 레이어 토글 패널, 정보 카드 (일반 DOM, 3D 아님)
```

### 핵심 계약 — Layer 인터페이스

```ts
interface Layer {
  init(scene: THREE.Scene): Promise<void>;
  update(time: number): void;       // 렌더 루프에서 매 프레임 호출
  setVisible(visible: boolean): void;
  dispose(): void;                  // 지오메트리/머티리얼/텍스처 명시적 해제
}
```

- 레이어끼리 서로 모른다. 새 레이어 추가 = 파일 하나 추가.
- 스코프 조절 수단: 시간이 남으면 레이어 추가, 모자라면 삭제.

## 3. 화면 구성 & UX

### 첫 화면

- 우주 배경 속 천천히 자전하는 지구.
- 로딩 연출: 지구가 어둡게 시작 → 텍스처 준비되면 도시 야경이 점등되듯 페이드인.
- 인트로 카메라 무브: 멀리서 지구로 다가오는 2~3초 연출, 스킵 가능.

### 조작

- OrbitControls — 드래그 회전, 휠/핀치 줌. 모바일 터치 동일.
- 조작 멈춘 뒤 몇 초 후 자동 자전으로 부드럽게 복귀.

### 레이어 패널

- 데스크톱: 좌하단 글래스모피즘 패널. 모바일: 하단 시트.
- 토글 3개: 🌋 지진, 🛰 ISS, ✨ 위성. 토글 시 페이드인/아웃.
- 기본값: 지진 + ISS 켜짐 (첫 화면부터 데이터가 보이도록).

### 정보 카드

- 마커 클릭(레이캐스팅) → 화면 가장자리에 카드 슬라이드인.
- 지진: 규모·위치·발생 시각. ISS: 현재 고도·속도·위경도 (지역명 역지오코딩은 스코프 밖).
- 3D 위 DOM 오버레이 — 텍스트 렌더링 품질과 접근성 확보.

### 기타

- 상단에 현재 UTC 시각 + "낮/밤 경계는 실시간" 라벨.
- 반응형: 모바일은 저사양 프로파일 자동 전환 (5장 참조).

## 4. 데이터 레이어 상세

### 공통

- `data/` 모듈이 API 호출·폴링·캐싱 담당, 레이어는 그리기만.
- 모든 API는 키 없이 브라우저 직접 호출 가능한 무료 공개 API. 서버 불필요.
- 위경도 → 3D 좌표 변환은 공용 유틸 하나로 전 레이어 공유.

### 🌋 지진 레이어 (USGS)

- 소스: USGS 실시간 GeoJSON 피드 `all_day.geojson` (최근 24시간), 5분 폴링.
- 표현: 규모에 따라 마커 크기·색 차등. M2 = 작은 점, M6+ = 크고 붉은 링 펄스 애니메이션.
- 최근 발생 지진일수록 밝게.

### 🛰 ISS 레이어

- 소스: Where the ISS at? API, 5초 폴링 (위경도·고도·속도).
- 표현: 실제 고도 비율 위치의 마커 + 지나온 궤적을 빛나는 꼬리선으로.
- 폴링 간격 사이는 lerp 보간 — 끊김 없는 이동.
- 클릭 시 정보 카드에 실시간 고도/속도.

### ✨ 위성 레이어 (CelesTrak)

- 소스: CelesTrak TLE 데이터. 하루 1회 갱신, localStorage 캐싱.
- 계산: satellite.js로 TLE → 실시간 위치 전파(propagation).
- 대상: 큐레이션된 100~150개 (Starlink 일부, GPS, 유명 위성). 수천 개는 스코프 밖.
- 표현: 작은 점 + 선택 위성만 궤도선. InstancedMesh로 드로우콜 1개.

### 🌍 지구 본체 (레이어가 아니라 무대)

- 낮/밤: 현재 시각 기준 태양 위치 계산 → 셰이더에서 낮/밤(야경) 텍스처 실시간 블렌딩.
  터미네이터(경계선)는 부드럽게.
- 대기: 프레넬 기반 가장자리 글로우 셰이더.
- 텍스처: NASA Blue Marble 계열 무료 텍스처 (2K~4K).

## 5. 에러 처리 & 성능

### 에러 처리 원칙: "데이터가 죽어도 지구는 산다"

- 지구본·셰이더는 API와 완전 독립 — 전 API 실패 시에도 첫 화면 임팩트 유지.
- 레이어별 독립 실패: 실패한 레이어만 비활성화 + 패널에 "일시적으로 사용 불가" 표시.
- 폴링 실패 시 지수 백오프 (5초 → 10초 → 30초 → 최대 1분). 복구 시 자동 재표시.
- 마지막 성공 데이터 localStorage 캐싱 — 재방문 시 즉시 그리기.
- 텍스처 로딩 실패 → 단색 폴백 머티리얼. 검은 화면 금지.

### 성능 예산: 데스크톱 60fps, 중급 모바일 30fps+

- InstancedMesh로 지진·위성 각 레이어당 드로우콜 1~2개, 총 10개 미만.
- 애니메이션 전부 GPU(셰이더 유니폼) — CPU에서 개별 객체 조작 금지.
- 위성 propagation은 초당 2회 계산 + 프레임 사이 보간.
- 저사양 프로파일: 첫 3초 fps 측정, 30 미만이면 텍스처 2K·위성 50개·픽셀 비율 1로
  자동 다운시프트. 수동 토글도 제공.
- 백그라운드 탭: 폴링·렌더 루프 일시정지.

### 메모리 규율

- `dispose()`에서 지오메트리·머티리얼·텍스처 명시적 해제. 토글 반복에도 누수 없음.
- 개발 중 `renderer.info`로 리소스 카운트 확인.

## 6. 테스팅

### 유닛 테스트 (Vitest) — 틀리기 쉬운 수학을 순수 함수로 분리해서 테스트

- 위경도 → 3D 좌표 변환 (극점·날짜변경선 경계 케이스)
- 태양 위치 계산 (특정 시각 → 알려진 태양 직하점과 대조)
- 지수 백오프 로직, USGS/TLE 응답 파싱 (mock fetch)
- 보간 유틸 (ISS lerp, 위성 위치 보간)

### 스모크 테스트 (Playwright)

- 페이지 로드 → 캔버스 렌더 확인 → 레이어 토글 3개 클릭 → 콘솔 에러 0개.
- 배포 전 마지막 관문.

### 비주얼 확인

- 셰이더·애니메이션은 브라우저 수동 확인 + 스크린샷 기록.
